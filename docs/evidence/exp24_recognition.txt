第二轮：两个 reducer 是独立轴 —— RMSNorm+max（论文自己的例子）
============================================================================================================
上一轮我把缺口叫"多生产端"，**这个说法是错的**。重推一遍：

  RMSNorm+max:  producer = mean(x^2)   <- 加法归约
                consumer = max         <- 取最大
                h(t,r,r') = t*sqrt(eps+r)/sqrt(eps+r')      （只是生产端对的纯量比值）

它只有**一个**生产端，只是这个生产端由**另一个 reducer** 产生。
生成器之前把 (producer=max, consumer=sum) 写死了，所以论文的旗舰例子根本表达不出来，
而原因和代数毫无关系。

改动：`producer_reducer` / `consumer_reducer` 变成两个独立字段，
模板统一成 `fold(repair(acc), block_reduce(term))`，只有那两个函数换。
`check_supported` 拒绝 "指数折叠 + max 消费者"（那不是同一个算子）。

生成出来的内核：
    m = 0.0                                      # 运行中的 mean(x^2)
    acc = -float('inf')                          # 运行中的 max
    m_new = m + tl.sum(tl.where(mask, (v*v)*(1.0/64.0), 0.0), axis=0)
    den = tl.maximum(m_new, 1e-30)
    scale = tl.where(m == 0.0, 1.0, tl.sqrt(m + 1e-06) * (1.0/tl.sqrt(den + 1e-06)))
    acc = tl.maximum(acc * scale, tl.max(tl.where(mask, v*(1.0/tl.sqrt(den+1e-06)), -float("inf")), axis=0))
    m = m_new
    tl.store(out_ptr + row, acc)

识别（写成人最容易写的形式 `(t*t).mean(-1)`）：
    d_rmsnorm_max -> rmsnorm_max   inferred N=4096, eps=1e-06
    * N 来自输入最后一维（所以解释器要读形状；.mean() 把行长度藏进了 op 里）
    * eps 来自项里解出来的
    * 生产端/消费者的判定按**依赖关系**（谁的结果出现在谁的操作数里），不是按图的先后顺序
      —— 之前假设"max 先出现"，在这个算子上会直接把两者标反

AOTI：mentions 0x -> 41x，cubins=1
数值：(64,4096) rel_err=2.622e-07 / (1024,3000) rel_err=2.883e-07

顺带修掉的：
  * `x**(-1/2)` 之前被正底数守卫拒绝。1/sqrt(x) 不需要正性假设（负数是 nan，正是定义）。
  * sp.solve 一次解多个未知数会掉进 `_solve_undetermined` 返回 None 然后崩；
    改成一次解一个（N 由生产端钉住，eps 由项钉住，本来就该分开解）。
  * 形状耦合的参数必须**按形状特化**。实测：用 N=4096 的算子去算 3000 列，
    rel_err=1.685e-01，正好是 sqrt(4096/3000)-1=0.168。这不是内核 bug，是测试用错了 N。
    （AOTI 的产物本来就是形状特化的。）
